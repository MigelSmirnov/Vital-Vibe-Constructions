## Перед активацией — локальному агенту с доступом к VPS

1. Использовать указанный SHA, а не движущуюся вершину ветки. Архив содержит только публичную `.deploy-dist`; конфигурация сервера в него не входит.
2. Проверить SHA-256 архива и `tar -xOf vital-vibe-vps-a1b83ad.tgz ./DEPLOYMENT_COMMIT`.
3. Зафиксировать реальный `readlink -f /srv/vital-vibe/current` и текущий `DEPLOYMENT_COMMIT` для отката. Последняя записанная production-версия — `ebd51356a925e84984bdfa2f520979fd11a44362`, но перед активацией сверить фактическую.
4. Проверить распакованный архив до переключения: `/ru/`, раскрытие 06, Joanic без нижнего дубля, RU detail link, четыре фото и ссылка на RU статью; мобильная ширина 390 px без горизонтального переполнения. Live browser/mobile QA в этой сессии не заявлена: Netlify закрыт team login.
5. Сохранить существующую схему nginx → Caddy и настройки путей/кеширования. Это обновление контента существующего VPS, не повторный DNS cutover. Исторические шаги изменения DNS из task/003 здесь не применять.
6. После отдельного поручения на публикацию выполнить существующий `deploy/vps/install-release.sh` с архивом и release ID. Скрипт сразу переключает `/srv/vital-vibe/current`; не запускать его как пробную проверку.
7. Проверить публичный `DEPLOYMENT_COMMIT`, RU homepage/detail/article и изображения на HTTPS. При ошибке использовать `deploy/vps/rollback-release.sh` с реально сохранённым предыдущим release ID. Не удалять предыдущий релиз.

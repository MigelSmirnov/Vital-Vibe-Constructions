# 001 — воспроизводимая проверка внешнего вида

Статус: первый технический слой собран; первый запуск и человеческое утверждение эталона ещё нужны.

## Зачем

На телефоне владелец заметил разные ширины карточек и неровные границы фотографий. Структурные проверки прошли, но таких проблем не показали. Нужен повторяемый способ увидеть результат после правок и сравнить его с согласованным видом.

## Объём первого шага

- Изучить доступный браузер и существующие средства скриншотов. Если нужен новый инструмент, сначала обосновать зависимость по AGENTS.md. При отсутствии среды честно записать ограничение.
- Снимать проверенную локальную сборку `.deploy-dist` через разрешённый локальный preview. Не использовать меняющийся публичный сайт как эталон и не запускать деплой ради проверки.
- Начать с фиксированных размеров **390 × 844**, **768 × 1024**, **1440 × 1000**, одинаковых языка, часового пояса, масштаба и версии браузера. Дождаться загрузки шрифтов и изображений, отключить анимации.
- Проверить главную ES / EN / RU, новую статью на трёх языках, галерею и один длинный проект El Raval. Пути брать из существующих контрактов; не создавать второй реестр маршрутов.
- Сохранить полные скриншоты и небольшую сводку: URL/маршрут, размер экрана, коммит, ошибки загрузки, горизонтальное переполнение. Отдельно проверить открытое мобильное меню и переключение языка статьи.
- Скриншоты и отчёты хранить как диагностические артефакты вне публичного пакета. В CI при добавлении этого шага сохранять их как артефакты проверки, а не публиковать на сайте.

## Реализация первого слоя

- `bash tools/visual/run.sh` запускает существующие проверки, собирает и валидирует `.deploy-dist`, затем запускает браузерную проверку.
- Playwright закреплён на версии `1.55.0` и устанавливается изолированно в игнорируемую `.visual-tools/`; зависимость не добавлена к runtime сайта.
- `tools/visual/check.mjs` поднимает локальный HTTP preview `.deploy-dist`, получает маршруты из архитектурных контрактов, снимает фиксированные размеры и проверяет загрузку, изображения и горизонтальное переполнение.
- Для главных страниц на 390 px отдельно открывается меню и сохраняется снимок. Для публичной Article проверяется соответствие языковых ссылок route contract.
- Результат пишется в `artifacts/visual/latest/` и исключён из git/релиза; workflow `Visual QA` загружает каталог как диагностический artifact.
- Playwright Chromium не считается поддерживаемой средой Termux/Android; воспроизводимый browser-run предусмотрен в GitHub Actions или на поддерживаемом desktop Linux/macOS. Отсутствие браузера не маскируется как успешная проверка.

## Готово, когда

- [x] Есть одна документированная команда, повторяемая из чистой копии репозитория в поддерживаемой среде.
- [ ] При одинаковой сборке получаются сопоставимые снимки; необходимые исключения описаны. Нужно подтвердить первым реальным запуском.
- [ ] Человек просмотрел снимки: границы карточек/фото, переносы заголовков, отступы, меню, подписи, язык и отсутствие обрезанного контента.
- [ ] Первый эталон выбран после визуального просмотра. Не объявлять первый автоматически снятый набор «правильным».
- [x] Сбой загрузки страницы или изображения отмечается как ошибка, а не маскируется пустым снимком.
- [x] Новые артефакты не попадают в `.deploy-dist`; существующие проверки должны пройти перед каждым browser-run, результаты и ограничения вносятся в handoff после подтверждённого запуска.

## Не расширять задачу без необходимости

Не внедрять сразу большую систему попиксельных сравнений, новый дизайн, новый логотип или переводы всех страниц. Сначала получить полезные снимки и исправить конкретные видимые дефекты. Сравнение с утверждёнными эталонами можно добавить следующим небольшим шагом.

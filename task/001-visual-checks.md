# 001 — воспроизводимая проверка внешнего вида

Статус: первый visual baseline утверждён владельцем 2026-09-13 после двух визуальных проходов и повторной browser-проверки.

## Зачем

Структурные проверки не показывают визуальные дефекты вроде тесных карточек, слишком длинной галереи, внутренних служебных статусов или несбалансированной desktop-композиции. Нужен повторяемый способ увидеть результат после правок и сравнить его с согласованным видом.

## Проверяемая матрица

- `.deploy-dist` открывается через локальный HTTP preview, а не через меняющийся публичный сайт.
- Viewport: **390 × 844**, **768 × 1024**, **1440 × 1000**.
- Главная ES / EN / RU, опубликованная статья на трёх языках, галерея и длинный проект El Raval.
- Отдельный снимок открытого мобильного меню.
- Фиксируются ошибки загрузки, сломанные изображения и горизонтальное переполнение.
- Для статьи проверяется соответствие языковых ссылок route contract.

## Реализация

- `bash tools/visual/run.sh` запускает существующие проверки, собирает и валидирует `.deploy-dist`, затем запускает браузерную проверку.
- Playwright закреплён на версии `1.55.0` и устанавливается изолированно в игнорируемую `.visual-tools/`; зависимость не добавлена к runtime сайта.
- `tools/visual/check.mjs` поднимает preview, дожидается изображений и шрифтов, отключает анимации и сохраняет диагностические снимки.
- Результат находится в `artifacts/visual/latest/` и в CI загружается отдельным artifact, но не публикуется на сайте.
- Chromium-run предусмотрен для GitHub Actions и поддерживаемого desktop Linux/macOS; Termux/Android не считается воспроизводимой браузерной средой.

## Первый просмотр — 2026-09-13

GitHub Actions run #4 на коммите `3e6d78acea4bbf51b6901cec2a34c4723db51743` был зелёным: 24 основных состояния, 0 ошибок загрузки, 0 сломанных изображений, 0 горизонтального переполнения.

Человеческий визуальный просмотр выявил три проблемы с высоким приоритетом:

1. галерея из 39 фотографий читалась как чрезмерно длинная почти однотипная лента;
2. El Raval показывал посетителю внутренний блок `Fotografías pendientes de incorporar`;
3. компактные project cards на мобильной главной были слишком тесными.

### Исправления первого прохода

- Галерея сохраняет 39/39 contract media, но группирует их по проекту/capability и показывает responsive preview-grid.
- `pending_technical_media` удалён из публичной Project-записи El Raval.
- На ширине до 720 px homepage project cards переходят в вертикальный формат: фотография сверху, метаданные и заголовок снизу.

GitHub Actions run #5 на коммите `7b41ed9ac081635f8fe2c7bdd629368b2e2e867e` завершился успешно.

## Второй просмотр — 2026-09-13

Следующими подтверждёнными проблемами были:

1. слишком высокая и плотная Smart Home секция на мобильном;
2. Article на desktop визуально тяготел к левому краю при большом свободном поле справа.

### Исправления второго прохода

- Smart Home: сохранены все capabilities и partner examples; уменьшены вертикальные интервалы, lead image до 240 px и четыре partner-preview до компактной 2×2 сетки по 145 px.
- На ES 390 px полная главная стала короче примерно на 500 px без удаления информации.
- Article: header, TOC/body и footer получили общий центрированный editorial frame 1040 px; body остаётся 720 px, TOC отдельный и sticky.
- Мобильная Article-композиция не менялась.

GitHub Actions `Visual QA` run #14 на коммите `712f180c9a8f7f9f273ec8eada27b0755d659931` завершился успешно. Полные project checks, VPS bundle и browser QA прошли.
